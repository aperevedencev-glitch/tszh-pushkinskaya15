# ТСЖ «Пушкинская 15» — сайт, CRM и Telegram-бот

Три связанные системы на обычном PHP-хостинге (Reg.ru): лендинг для жильцов, собственная CRM и Telegram-бот `@tszh_pushkinskaya15_bot`. Любое обращение с сайта или из бота попадает в одну карточку жильца в CRM.

Работа идёт по этапам. Готовы **этап 1 — сайт**, **этап 2 — Telegram-бот** на вебхуке, **этап 3 — CRM** (`/crm/`) , **этап 4 — сквозная связка** (8 обязательных сценариев проверены автотестом через браузер, вебхук и cron) и **этап 5 — развёртывание**: мастер установки, ежедневные бэкапы, страница состояния `/crm/health`, подключение вебхука, HTTPS.

**Как запустить на Reg.ru — [docs/DEPLOY_REGRU.md](docs/DEPLOY_REGRU.md).**

## Структура

```
public/                 ← публичная папка сайта (корень домена на хостинге)
  index.php             лендинг (шаблон private/templates/landing.html)
  install.php           мастер первой установки: таблицы, руководитель, секреты; после установки блокируется и удаляет себя
  policy.php            политика обработки ПДн → /politika/
  404.html, robots.php, sitemap.php, site.webmanifest, иконки
  api/lead.php          приём заявки с сайта
  bot/webhook.php       вебхук Telegram-бота (проверка секретного заголовка, отсев повторов)
  crm/                  точки входа CRM (код страниц — в private/crm/pages); /crm/health — состояние системы
  assets/               стили, скрипт, шрифты, картинки — всё своё, без внешних CDN
  .htaccess             правила Apache: переадресация на HTTPS, HSTS, заголовки безопасности, кэш
private/                ← закрытая папка, вне публичной (на хостинге — рядом с ней)
  config.example.php    образец настроек → скопировать в config.php и заполнить
  bootstrap.php, lib/   общее ядро: контакты, согласия, сделки L-…, источники, задачи, очередь в Telegram
  sql/schema.mysql.sql  схема базы (для SQLite преобразуется автоматически)
  sql/kb_seed.php       стартовые ответы бота (дальше правятся в CRM)
  cron/run.php          фоновые задачи (каждую минуту): повторная отправка в Telegram, напоминания о задачах,
                        очистка черновиков бота; раз в сутки — бэкап базы (14 дней) и обезличивание по сроку хранения
  tools/webhook.php     вебхук бота из консоли: info | set | delete (с подтверждением)
  tools/restore.php     восстановление базы из бэкапа (с подтверждением и страховочным бэкапом)
  crm/pages/            страницы CRM: канбан, карточка, заявки, задачи, отчёты, ответы бота, сотрудники, настройки
  templates/            HTML-шаблоны страниц
  logs/, backups/, data/  журналы, бэкапы, файл SQLite — не попадают в git
tests/                  автотесты
dev/router.php          локальный запуск без Apache
dev/build_release.sh    архив public/ + private/ для загрузки на хостинг (без секретов и данных)
docs/DEPLOY_REGRU.md    пошаговый запуск на Reg.ru: база, SSL, файлы, мастер, cron, вебхук, бэкапы
docs/NEEDED.md          что нужно от заказчика
```

Файлы в корне репозитория (`index.html`, `app.html` и др.) — старая статическая демо-версия для GitHub Pages. Она не используется новой системой; на этапе 5 её заменит переадресация на домен Reg.ru.

## Правила, заложенные в код

- Данные жильцов записываются только в базу на сервере в России. Telegram — канал связи.
- Секреты — только в `private/config.php`: он вне публичной папки и в `.gitignore`.
- Ни одного внешнего запроса на сайте: шрифты, картинки и скрипты лежат на своём сервере (проверяется автотестом).
- Без галочки согласия заявка не сохраняется. Согласие записывается с версией политики.
- В журналах, адресах и уведомлениях менеджерам — без имён и телефонов.
- Все SQL-запросы подготовленные; частота заявок ограничена; ловушки для ботов.

## Локальный запуск

```bash
cp private/config.example.php private/config.php   # указать db sqlite и app_secret
php -r 'require "private/bootstrap.php"; Schema::create(App::db());'
php -S 127.0.0.1:8080 -t public dev/router.php
```

## Тесты

Всё сразу — чистая установка в `/var/www/tszh` (как на хостинге: `public/` + `private/`), имитация Telegram, Apache, затем все наборы:

```bash
sudo TEST_DB_PASS=… bash tests/run_all.sh [папка_для_скриншотов]
```

`tests/scenarios_test.py` — 8 сквозных сценариев этапа 4: UTM → форма → карточка и уведомление ≤ 10 с; «Продолжить в Telegram»;
бот, потом сайт с тем же телефоном; ответ менеджера из карточки и ответ клиента; заявка ночью → задача на утро → отчёт;
«Оплачено» → выручка у первого источника; «Удалить мои данные» → обезличивание и audit_log; Telegram недоступен → повторная отправка.

`tests/deploy_http_test.py` и `tests/deploy_test.php` — этап 5: мастер установки (ключ, CSRF, слабые пароли, самоудаление, замок),
секреты в config.php, бэкап и восстановление байт в байт (SQLite и MySQL), хранение 14 дней, `/crm/health` (роли, ни одного секрета на странице),
подключение вебхука только по кодовому слову и только на https, переадресация на HTTPS и HSTS.

По отдельности:

```bash
php tests/core_test.php                     # ядро на SQLite в памяти
TEST_DB=mysql TEST_DB_PASS=… php tests/core_test.php   # то же на MySQL
python3 tests/e2e_site.py                   # браузер: 375/390/1440 px, форма, UTM, внешние запросы, 404
php tests/bot_test.php                      # бот: 45 сценариев, Telegram подменён, время зафиксировано
python3 tests/webhook_http_test.py          # вебхук по HTTP через Apache + имитация Telegram (tests/mock_telegram.php)
php tests/crm_test.php                      # CRM: отчёты, первый ответ, обезличивание, автоудаление, напоминания
python3 tests/e2e_crm.py                    # CRM в браузере: вход, роли, CSRF, канбан, ответ клиенту, отчёты, 152-ФЗ
php tests/seed_demo.php private             # тестовые сотрудники и заявки — только для локальной проверки
```

## CRM

Роли: **руководитель** видит всё, отчёты, сотрудников и настройки; **менеджер** — свои заявки и общий входящий поток (этап «Новая»), чужую новую заявку может «Взять себе».
Канбан: перетаскивание мышью или выбор этапа в карточке; для «Отказ» причина обязательна; счётчик и сумма по колонке.
Карточка: контакт, источник и UTM (первое и последнее касание), вся переписка сайта и бота, ответ в Telegram со статусом доставки, заметки, задачи, история изменений.
152-ФЗ: просмотр согласий, «Обезличить данные» (руководитель, с подтверждением), автоматическое обезличивание через `retention_months`.

## Бот

Меню: «Оставить заявку», «Цены и сроки», «Частые вопросы», «Связаться с менеджером», «Удалить мои данные».
Заявка: имя → телефон (кнопкой или вручную) → суть → «Согласен» → номер L-…. До согласия в CRM ничего не пишется.
Ссылка «Продолжить в Telegram» с сайта привязывает Telegram к той же карточке и той же заявке.
Сотрудник привязывает свой Telegram для уведомлений командой `/link КОД` (код — в профиле CRM).
