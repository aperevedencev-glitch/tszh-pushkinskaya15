# Запуск на хостинге Reg.ru — пошагово

Инструкция для виртуального хостинга Reg.ru с панелью **ISPmanager**. Займёт около часа, плюс ожидание SSL-сертификата.
Ничего устанавливать на свой компьютер не нужно: всё делается в браузере. SSH пригодится, но он не обязателен.

Во всех примерах:
- `u1234567` — ваш логин хостинга (виден в панели и в письме от Reg.ru);
- `ваш-домен.ru` — домен сайта;
- `8.3` — версия PHP. Подойдёт любая от 8.1.

Названия кнопок в панели иногда меняются. Если кнопка называется иначе, смотрите справку Reg.ru по ссылкам в конце.

---

## Что получится на сервере

```
/var/www/u1234567/data/              ← домашняя папка хостинга
├── private/                         ← папка private целиком: код, настройки, база SQLite, журналы, бэкапы
│   ├── config.php                   ← ваши настройки и секреты (создаёте на шаге 5)
│   ├── cron/run.php                 ← фоновые задачи, запуск каждую минуту
│   ├── tools/                       ← вебхук и восстановление из консоли
│   └── backups/                     ← ежедневные бэкапы базы, 14 дней
└── www/
    └── ваш-домен.ru/                ← СОДЕРЖИМОЕ папки public: index.php, .htaccess, assets/, crm/, bot/, api/, install.php …
```

Папка `private` лежит **вне** папки сайта, поэтому из интернета её не открыть. Сайт находит её сам — на два уровня выше папки сайта.

## Шаг 1. Сайт и версия PHP

1. Домен должен быть направлен на хостинг Reg.ru (DNS-серверы `ns1.hosting.reg.ru` и `ns2.hosting.reg.ru` или A-запись на IP хостинга). Если домен куплен в Reg.ru вместе с хостингом, это обычно уже сделано.
2. ISPmanager → **«Сайты»** → **«Создать сайт»** → впишите домен.
3. Сразу отметьте **«Защищенное соединение (SSL)»**, затем в блоке «SSL-сертификат» выберите **«Новый Let's Encrypt сертификат»**. Галочку «Перенаправлять HTTP-запросы в HTTPS» ставить можно, но не обязательно: переадресация уже прописана в `.htaccess`.
4. В настройках сайта выберите **PHP 8.3** (подойдёт любая версия от 8.1).

Если сайт уже создан: «Сайты» → выберите домен → «Изменить» → включите SSL. Затем «SSL-сертификаты» → «Добавить сертификат» → «Let's Encrypt» → «Выпустить».

Сертификат выпускается до 24 часов. Готовность — когда `https://ваш-домен.ru` открывается без предупреждения браузера. **Не переходите к шагу 8 (бот), пока https не работает.**

## Шаг 2. База данных MySQL

ISPmanager → **«Базы данных»** → **«Создать»**:
- **Имя базы**, например `tszh`. Панель может добавить префикс: тогда полное имя будет `u1234567_tszh`.
- **Пользователь** — новый, например `tszh` (полное имя тоже может получиться `u1234567_tszh`).
- **Пароль** — сгенерируйте кнопкой в панели и сохраните в менеджере паролей. Никому его не пересылайте.
- **Кодировка** — `utf8mb4`, если панель предлагает выбор.

Запишите **полные** имя базы и пользователя — так, как их показывает список баз. Сервер базы — `localhost`.

## Шаг 3. Файлы

Возьмите файлы проекта одним из способов:
- **Архив.** Возьмите архив `tszh-pushkinskaya15-ДАТА.zip`: его собирает `bash dev/build_release.sh`, или его пришлёт разработчик. В нём только папки `public` и `private`, без секретов.
- **GitHub.** Страница репозитория → «Code» → «Download ZIP». Из архива нужны только папки `public` и `private`. Остальное (старая статичная демо-версия, `tests`, `docs`) на хостинг не загружайте.

Загрузка через ISPmanager → **«Менеджер файлов»**:
1. Откройте домашнюю папку (вы попадаете в неё сразу) и загрузите архив, затем распакуйте его (кнопка «Извлечь» / «Распаковать»).
2. Папку **`private`** оставьте в домашней папке: `/var/www/u1234567/data/private`.
3. **Содержимое** папки `public` перенесите в `www/ваш-домен.ru/`. Скрытые файлы `.htaccess` (в корне и в `bot/`) тоже должны оказаться там. Если в папке сайта лежала заглушка `index.html` от хостинга — удалите её.
4. Удалите архив и пустую папку `public`.

Права оставьте стандартные: 755 на папки, 644 на файлы. На `config.php` мастер установки сам поставит 600.

Проверка: `https://ваш-домен.ru` открывает лендинг. Пока данных нет, на нём видны плейсхолдеры «[Нужно от заказчика: …]».

## Шаг 4. Токен бота

В Telegram у **@BotFather**: `/mybots` → `@tszh_pushkinskaya15_bot` → «API Token». Токен вписываете **только** в `config.php` (шаг 5). Не пересылайте его в чатах и почте и не вставляйте в код.

## Шаг 5. Настройки — `private/config.php`

В менеджере файлов откройте `private`, скопируйте `config.example.php` в файл с именем **`config.php`** и откройте его на редактирование. Впишите:

| Строка | Что вписать |
|---|---|
| `'site_url'` | `https://ваш-домен.ru` — без слэша в конце. Для домена `.рф` впишите адрес в punycode (`https://xn--…`). |
| `'db'` → `'name'`, `'user'`, `'pass'` | полные имя базы, пользователя и пароль из шага 2 |
| `'install_key'` | любая фраза от 8 символов. Её нужно будет ввести в мастере установки |
| `'telegram'` → `'bot_token'` | токен из шага 4 |
| `'company'` | наименование, адреса, телефоны, e-mail, ответственный за ПДн. Список — в `docs/NEEDED.md` |
| `'prices'` | цены, если правление их утвердило |

**`app_secret` и `webhook_secret` оставьте пустыми кавычками `''`.** Мастер установки сам впишет туда случайные значения и нигде их не покажет.

Сохраните файл.

## Шаг 6. Мастер установки

Откройте `https://ваш-домен.ru/install.php`.

1. **Проверка сервера.** Все пункты должны быть зелёными. Если какой-то красный, под ним написано, что исправить. Исправьте и обновите страницу.
2. **Руководитель.** Введите ключ установки (`install_key`), имя, логин и пароль: не короче 10 символов, логин внутри пароля нельзя.
3. Нажмите **«Установить»**.

Мастер:
- создаёт таблицы и загружает стартовые ответы бота;
- заводит руководителя и вписывает секреты в `config.php`;
- блокирует себя (файл `private/data/install.lock`) и удаляет `install.php`.

Если удалить файл не получилось, мастер так и скажет. Тогда удалите `install.php` вручную — повторно он всё равно не откроется.

**На странице «Установка завершена» показана точная команда для cron — скопируйте её.**

После установки строку `install_key` в `config.php` можно стереть.

## Шаг 7. Cron — фоновые задачи

ISPmanager → **«Планировщик (cron)»** → **«Создать»**:
- **Команда** — из мастера установки, например:
  ```
  /opt/php/8.3/bin/php -f /var/www/u1234567/data/private/cron/run.php
  ```
  Номер версии PHP в пути должен совпадать с версией сайта.
- **Расписание** — каждую минуту: `* * * * *` (во всех полях «каждую»).

Что делает cron:
- каждую минуту повторно отправляет в Telegram всё, что не ушло сразу, и напоминает о задачах;
- раз в сутки, после 03:00, делает бэкап базы и обезличивает данные старше 12 месяцев.

Проверка: войдите в CRM (`https://ваш-домен.ru/crm/`) → **«Состояние»** (`/crm/health`). Через 1–2 минуты пункт **«Cron»** должен стать зелёным. Первый бэкап можно сделать сразу кнопкой **«Сделать бэкап сейчас»**.

## Шаг 8. Подключение бота (вебхук)

> Это действие переключает бота на сервер. Если бот раньше работал где-то ещё (например, старый бот на Python), он перестанет получать сообщения — выключите его.

Перед подключением проверьте:
1. `https://ваш-домен.ru` открывается без предупреждений.
2. На странице «Состояние» нет красных пунктов в группах «Настройки» и «База данных».

**Через CRM.** Откройте «Состояние» → блок «Действия» → впишите `ПОДКЛЮЧИТЬ` → **«Подключить вебхук»**. Система:
- отправит в Telegram `setWebhook`: адрес `https://ваш-домен.ru/bot/webhook.php`, секретный заголовок `secret_token` и только нужные типы сообщений;
- сразу проверит результат через `getWebhookInfo`.

Пункт **«Вебхук бота»** станет зелёным.

**Через SSH**, если удобнее:
```bash
cd ~/private/tools
/opt/php/8.3/bin/php webhook.php set        # спросит домен для подтверждения
/opt/php/8.3/bin/php webhook.php info       # что сейчас знает Telegram: адрес, очередь, последняя ошибка
```

**Проверка руками:** напишите боту `/start` и оставьте тестовую заявку. Она должна появиться в CRM на канбане, а ответственному прийти уведомление в Telegram. Его получит только сотрудник, который уже привязал Telegram (шаг 9).

## Шаг 9. Сотрудники и календарь

1. CRM → **«Сотрудники»** → добавьте двух менеджеров. Временный пароль система покажет один раз — передайте его лично.
2. Каждый сотрудник входит в CRM и меняет пароль в **профиле**. Там же он получает код и отправляет боту `/link КОД`, чтобы получать уведомления о заявках.
3. **«Настройки»** → праздники и перенесённые рабочие дни на год. Без них заявки в праздники считаются пришедшими в рабочее время.

## Шаг 10. Итоговая проверка

- [ ] `/crm/health`: все пункты зелёные. Жёлтым может остаться «Последняя ошибка», если она старая, — нажмите «Отметить как просмотренную».
- [ ] Заявка с сайта (форма внизу лендинга) появилась в CRM, менеджеру пришло уведомление.
- [ ] Кнопка «Продолжить в Telegram» после заявки открывает бота, и бот узнаёт номер заявки.
- [ ] Ответ менеджера из карточки пришёл в Telegram, ответ жильца появился в карточке.
- [ ] `https://ваш-домен.ru/install.php` → «не найдено».
- [ ] `http://ваш-домен.ru` переадресует на `https://`.

Тестовые заявки удаляются так: карточка контакта → «Обезличить данные» (только руководитель, с подтверждением). Это необратимо.

## Бэкапы

- Каждую ночь после 03:00 в `private/backups/` появляется файл `db-ГГГГ-ММ-ДД_ЧЧММСС.mysql.sql.gz`. Файлы старше 14 дней удаляются автоматически. Срок хранения задаётся в `config.php`, строка `'backup' => ['keep_days' => 14]`.
- В бэкапе — **персональные данные жильцов**. Не скачивайте его без необходимости, не пересылайте и не храните в зарубежных облаках.
- Свежесть бэкапа видна в «Состоянии»: если он старше суток, пункт «Бэкап базы» красный.
- Reg.ru тоже делает собственные резервные копии хостинга. Наши бэкапы — дополнительная страховка на уровне базы.

**Восстановление** (заменяет текущие данные — делайте только при необходимости):
- **phpMyAdmin.** ISPmanager → «Базы данных» → база → phpMyAdmin → «Импорт» → файл `.sql.gz` → «Вперёд».
- **SSH:**
  ```bash
  cd ~/private/tools
  /opt/php/8.3/bin/php restore.php                                   # список бэкапов
  /opt/php/8.3/bin/php restore.php db-2026-10-09_030001.mysql.sql.gz # спросит слово ВОССТАНОВИТЬ
  ```
  Перед восстановлением автоматически сохраняется бэкап текущего состояния. Обрезанный или повреждённый файл не применяется вовсе.

## Обновление версии

1. Сделайте бэкап: «Состояние» → «Сделать бэкап сейчас».
2. Загрузите новые файлы поверх старых. **Не трогайте** `private/config.php`, `private/data/`, `private/logs/` и `private/backups/`. В архиве из `dev/build_release.sh` этих файлов и так нет.
3. Мастер установки при обновлении не нужен: `install.php` из нового архива сразу удалите.
4. Откройте «Состояние» и убедитесь, что всё зелёное.

## Если что-то не работает

| Что видно | Где смотреть | Что сделать |
|---|---|---|
| Белая страница или «500» | `private/logs/php-error.log` | Проверить версию PHP (8.1+) и путь к папке `private` |
| «Не найдена папка private/» | — | `private` должна лежать в `/var/www/u1234567/data/`, рядом с `www` |
| Мастер: «Нет подключения к базе» | `config.php` → `db` | Полные имя базы и пользователя — с префиксом `u1234567_` |
| «Cron» красный | Планировщик в ISPmanager | Путь к PHP и к `run.php`, расписание «каждую минуту» |
| «Вебхук бота» красный, «Wrong response … 403» | `config.php` → `webhook_secret` | Секрет меняли после подключения — подключите вебхук заново |
| «Вебхук бота» красный, «SSL error» | SSL-сертификат | Дождаться выпуска, проверить `https://` в браузере |
| Уведомления не приходят | «Состояние» → «Очередь уведомлений», «Сотрудники получают уведомления» | Сотрудник не привязал Telegram или заблокировал бота |
| На сайте «[Нужно от заказчика: …]» | `docs/NEEDED.md` | Вписать данные ТСЖ в `config.php` → `company` |

## Если MySQL недоступен

Систему можно запустить на SQLite (база — файл `private/data/crm.sqlite`): в `config.php` закомментируйте блок `'db' => [...]` с MySQL и раскомментируйте строку с `sqlite`. Бэкапы и восстановление работают так же. Для ТСЖ с двумя-тремя сотрудниками производительности хватает, но MySQL предпочтительнее.
